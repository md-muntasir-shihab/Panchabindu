Inspect complete call chain, actors and downstream side effects; cross-role exploitability remains NOT TESTED.
- **P1 customer ownership risk:** `supabase/migrations/0008_phase2_schema_rls_and_gl_completion.sql:488-499` falls back to JWT `user_metadata.phone` in `fn_current_customer_phone()`, used in ownership policies. User-editability, JWT issuance, actual grants and deployed RLS must be verified; never treat user-editable metadata as verified identity.
- **P1 RLS view isolation risk:** `supabase/migrations/0007_rls_policies.sql:181-213` defines `v_vendor_masked_orders` with no explicit vendor WHERE clause, and migration `0008:560` grants SELECT to `authenticated`. - **P1 deterministic secret fallback:** `src/lib/security/crypto-session.ts:20-35` uses a predictable development-derived key if the environment key is missing or short unless both NODE_ENV is production and a separate strict flag is enabled. Session verification and encryption use this key derivation; deployment configuration, practical attack conditions and actual stored data exposure NOT VERIFIED. - **P1 stock concurrency:** `src/lib/inventory/phase3-inventory-order-engine.ts:344-352` implements a module-local Promise queue. It cannot by itself serialize work across independent processes/instances or provide database transactions; multi-instance overselling tests NOT RUN.
