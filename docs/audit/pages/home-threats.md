## 2. Homepage Threat Matrix (OWASP Top 10:2025 & OWASP API Top 10:2023)

| ID | Threat / Abuse Case | Framework Ref | Attack Surface on `/` | Pre-Audit State | Fix & Proof |
| --- | --- | --- | --- | --- | --- |
| T-01 | Missing HTTP Security Headers & Server Fingerprinting | OWASP A02:2025 Security Misconfiguration | All `/api/*` responses (`app.ts`) | `X-Powered-By: Express` exposed; missing `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` (`[EXECUTED]`) | Disabled `x-powered-by`, added `nosniff`, `strict-origin-when-cross-origin`, and `Permissions-Policy` in `app.ts`; iframe embedding preserved. Verified by `test:home:api` (`[EXECUTED]`). |
| T-02 | Wildcard Cross-Origin Resource Sharing (`cors()`) | OWASP A02:2025 / API8:2023 | Express `app.ts` global CORS middleware | Wildcard `cors()` reflected any third-party origin (`[TRACED]`) | Replaced with strict allowlist (`APP_URL`, `CORS_ALLOWED_ORIGINS`, same-host/localhost dev only). Verified untrusted `Origin: https://evil-attacker.example` rejected in `test:home:api` (`[EXECUTED]`). |
| T-03 | Unhandled `URIError` DoS / 503 Crash via Malformed `pagePath` | OWASP A04:2025 / A10:2025 Mishandling of Exceptional Conditions | `GET /api/page-data?pagePath=/%E0%A4%A` | Returned `503 SERVICE_UNAVAILABLE` crash (`[EXECUTED]`) | Added `512`-char length bound and `try/catch` around `decodeURIComponent`, returning `400 INVALID_PATH` with `Cache-Control: no-store`. Verified in `test:home:api` (`[EXECUTED]`). |
| T-04 | Numeric Poisoning / `NaN` & Negative Subtotal on Delivery Quote API | OWASP API3/API8:2023 / Business Logic Abuse | `GET /api/storefront?districtId=1&weightGrams=abc&subtotalPoisha=-999` | Returned `200 OK` with corrupted `NaN` quote calculation (`[EXECUTED]`) | Added strict `parseBoundedIntParam` bounds (`districtId 1..999`, `weightGrams 1..1000000`, `subtotalPoisha 0..1000000000`, slug/category length caps) returning `400`. Verified across 6 abuse payloads in `test:home:api` (`[EXECUTED]`). |
| T-05 | DOM XSS / Unsafe URI Schemes in CMS Image, Hero CTA, WhatsApp & Social Links | OWASP A05:2025 Injection | `productImageUrl`, `hero.ctaHref`, `socialLinks`, `whatsappNumber`, `supportPhone` | `productImageUrl` lacked strict scheme allowlist; hero/social links trusted arbitrary strings (`[TRACED]`) | Enforced strict safe URL allowlist (relative `/` without `//` or control chars, or `https:` without credentials; rejects `javascript:`, `data:`, `vbscript:`) and sanitized phone/WhatsApp digits. Verified in code & search XSS browser test (`[EXECUTED]`). |
| T-06 | Sensitive Internal Field Disclosure on Public Catalog API | OWASP API3:2023 Broken Object Property Level Authorization | `GET /api/page-data?pagePath=/` | Tested payload for `vendorId`, `supplierCostPoisha`, `platformMarginPoisha`, `passwordHash`, `sessionToken`, `apiKey` | Zero internal fields leaked. Guarded permanently by recursive forbidden-key check in `test:home:api` (`[EXECUTED]`). |
| T-07 | Public Exposure of Internal Admin & Vendor Portal Entry Links | OWASP A01:2025 / Attack Surface Reduction | Public navbar, mobile nav drawer, and footer (`storefront-shell.tsx`) | `ADMIN` and `VENDOR` links publicly visible in header, mobile menu, and footer (`[EXECUTED]`) | Removed `/admin` and `/vendor` links from public storefront chrome per user decision. Direct routes stay server-side RBAC-protected (note: `scripts/src/preview.mjs` enables `PANCHABINDU_BYPASS_AUTH=1` in offline preview only and hard-exits on `NODE_ENV=production` or `VERCEL`). Verified 0 exposed links across all 9 viewports + drawers (`[EXECUTED]`). |
| T-08 | Unbounded Request Payload Size | OWASP API4:2023 Unrestricted Resource Consumption | Express JSON/urlencoded parsers (`app.ts`) | No explicit body size cap configured on Express parsers (`[TRACED]`) | Set explicit `limit: '1mb'` on `express.json` and `express.urlencoded` in `app.ts` (`[TRACED]`). |
| T-09 | Client-Side Cart/Price Tampering | E-Commerce Integrity | `useCartStore` (`localStorage`) -> `/checkout` -> `POST /api/orders` | Cart lives in `localStorage` for UX convenience | Order totals, discounts, and prices are recomputed server-side during order submission (verified in `test:domain` & `test:security`; full checkout audit deferred to `/checkout` page audit) (`[TRACED]`). |
