# Known limitations — 2026-11-13

- The system is not production-ready. Private KYC image upload and document review have isolated tests with mock storage; real Supabase Storage, browser journeys, identity verification policy, document expiry/retention/deletion, detailed vendor lifecycle, formal disputes, reconciled statements and complete portal navigation remain missing or unverified. General support tickets and ledger CSV export are implemented locally but have not been browser/live tested.
- Pending-to-active requires complete onboarding answers and an audited super-admin review reason, but this is not KYC document verification. Other privileged business workflows and every button have not been fully audited.
- Optional self-service MFA is implemented and API-tested locally, but browser/live database testing and safe existing-account migration are not complete; existing 2FA remains enforced where configured. Security-reset currently requires fresh super-admin TOTP even when no admin has enrolled. This needs a secure recovery design, not a bypass.
- JSONB persistence is not a relational conversion, Supabase Auth mapping, or proof of Postgres RLS and concurrent inventory/finance correctness. No production write or migration performed.
- Global emergency off is implemented at the shared imported API transaction boundary with audited super-admin recovery and locally tested, but production Postgres, deployment, browser UI and all external/background write paths still require independent verification. The separate automation kill switch is not equivalent.
- Real integrations and end-to-end authenticated production, every responsive width, accessibility and real database RLS are not verified. Courier tracking reports NOT_INTEGRATED, not simulated success.
- Admin/vendor use the same browser cookie and cannot simultaneously retain separate identities in one browser profile.
- Existing address book is browser-local; order-derived profile is account-scoped but not editable as a separate address book.
- Lint script is not configured in the workspace packages. Local build reports sourcemap and large-chunk warnings.

- Vendor statement bucket roll-forward is based solely on stored ledger entries, not reconciled to GL, orders or bank/payment evidence. The existing payout-hold calculation may remain overstated after a zero-amount PAYOUT_DISBURSED entry; investigate and reconcile source records before relying on payout-hold totals. The statement does not present that derived hold as reconciled.

- Integration evidence, 2026-11-13: courier summary now reports not integrated even if credentials are present; the SMS OTP placeholder reports `dispatched: false`. Neither establishes a provider connection. The isolated Chromium fixture exercised vendor login, support creation and statement display at 375px and 1280px, not all portal screens, accessibility or live services. Provider-backed delivery, KYC storage, Postgres concurrency and adversarial RLS remain untested.
- Courier auto-sync is disabled both at its cron and legacy direct-function boundaries; the unverified generic HMAC webhook also fails closed even for valid signatures. No provider-specific webhook/polling contract has been verified; there is no automatic status update until a real integration and sandbox tests are completed (see `docs/runbooks/courier-tracking-status.md`).
- Checkout fixture browser test now covers guest order submission and district/thana reset using disposable data. The live checkout failure described by the user has not been reproduced or authenticated against production; the selected-field UX fix is branch-only. Default legal/about copy uses Panchabindu for new seed data, but existing saved production branding is unchanged until explicitly updated through an authorized workflow.
- Admin workspace crash: an authenticated transition previously invoked an additional React hook after early returns, reproducible in the isolated browser fixture as “Rendered more hooks than during the previous render.” The branch removes that conditional hook and tests fixture login, workspace reload and logout. Production login, production deployment of this fix and all admin modules remain unverified.
- Product Studio linkage review displays vendor/category availability within the current role-scoped workspace and stored variant fields only. It does not certify end-to-end connectivity. Isolated audit tests cover vendor mapping/pricing, catalog import, storefront revalidation, media and related domains; checkout tests cover quote/order totals and unavailable products. These do not establish production product, order, payout, review, printing or external courier functionality. Courier tracking remains not integrated. The old inspector displayed hard-coded order counts and delivery prices; those claims were removed rather than presented as live data.
- Manual payment UI: the super-admin workspace shows existing per-order submission amounts and verification status, and defaults new bKash entries to pending with an explicit amount. This is not a reconciled provider statement. Although the user authorized manual Nagad/Rocket accounting, those channels are not implemented in the accounting ledger and remain disabled; do not treat them as available or verified. The ledger and maker-checker flow require provider-aware implementation and tests before activation. No provider is automatically verified.
- Customer message sheet opens WhatsApp/SMS in the user's app without claiming delivery or recording a fabricated sent status. Secure order-status links use the current origin and unexpired order token; they show the site's recorded order state, not a live courier feed. Actual delivery, provider tracking and production behavior are unverified.
- Customer account/order detail UI: isolated browser coverage checks email registration, signed-in checkout, order details, logout and sign-in on 375px and 1280px viewports; security tests separately exercise account ownership and guest-order isolation. No production login, order, device, or real courier test was performed. Addresses and wishlist are browser-local, not account-synchronized; secure tracking links show stored order status, not live courier updates.
- Print fitting: isolated Chromium-generated PDFs were checked for one page per A4/4×6 order and for batch page counts; overlarge content is blocked instead of clipped, and deselected copies are removed from the printable DOM. Physical printers, printer margins, ink/thermal quality, barcode scanning and other browsers are not tested. Print request counts are recorded before fit validation and can include cancelled or blocked attempts; they do not prove a successful print.

- Order/vendor/courier safety quarantine (local only): legacy pickup manifest and batch handover, webhook simulation/internal processing, courier remittance (including CSV), automatic delivery/return financial posting, and four-way return settlement fail closed. They previously could fabricate references, bypass inventory transitions or duplicate/misstate ledger entries. Manual order delivery does not prove courier remittance or automatically create vendor earnings. Existing historical rows are not corrected or reconciled. Vendor fulfillment-group actions have separate inventory/escrow logic that has not been proven reconciled with the general ledger, payment collection, multiple lines and all parent-order paths; do not rely on it for live payouts without an end-to-end accounting and inventory audit. No live courier integration, production migration, or external payment was performed.
- Tracking by order ID is available only for the authenticated account that placed the order; guest orders are not claimed by phone/email or exposed by sequential ID. Guests need their original secure tracking link/token. The tracking page shows store-recorded status, not live courier data. Local browser tests cover owner, logged-out and other-account access on mobile and desktop; no production verification performed.
- Courier accounts screen: recorded delivered and shipped COD projections are shown per provider, including historical `remitted` statuses, and are not verified receivables. Historical ledger rows are unverified and may be fabricated or duplicated; no automated deduction, payout prediction, fabricated proof, or net balance is presented. Confirmed net receivables require externally verified delivery, collection, fees, adjustments and receipts plus a future idempotent maker-checker reconciliation workflow. Live courier integration and remittance settlement remain unavailable. The screen is restricted to super admins; data has not been reconciled against production statements.
- Storefront safe-area behavior is tested in isolated Chromium with simulated CSS insets at 320, 375, 768, 844 (landscape), 1024 and 1440px, including mobile purchase/checkout bars, footer and cart sheet. Actual iOS/Android cutouts, browser chrome, standalone PWA mode, virtual keyboards, and device rotation have not been tested on physical devices.
