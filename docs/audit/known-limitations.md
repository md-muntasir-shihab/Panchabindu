# Known limitations — 2026-11-13

- The system is not production-ready. Private KYC image upload and document review have isolated tests with mock storage; real Supabase Storage, browser journeys, identity verification policy, document expiry/retention/deletion, detailed vendor lifecycle, formal disputes, reconciled statements and complete portal navigation remain missing or unverified. General support tickets and ledger CSV export are implemented locally but have not been browser/live tested.
- Pending-to-active requires complete onboarding answers and an audited super-admin review reason, but this is not KYC document verification. Other privileged business workflows and every button have not been fully audited.
- Optional self-service MFA is implemented and API-tested locally, but browser/live database testing and safe existing-account migration are not complete; existing 2FA remains enforced where configured. Security-reset currently requires fresh super-admin TOTP even when no admin has enrolled. This needs a secure recovery design, not a bypass.
- JSONB persistence is not a relational conversion, Supabase Auth mapping, or proof of Postgres RLS and concurrent inventory/finance correctness. No production write or migration performed.
- Global emergency off is implemented at the shared imported API transaction boundary with audited super-admin recovery and locally tested, but production Postgres, deployment, browser UI and all external/background write paths still require independent verification. The separate automation kill switch is not equivalent.
- Real integrations and end-to-end authenticated production, every responsive width, accessibility and real database RLS are not verified. Courier tracking reports NOT_INTEGRATED, not simulated success.
- Admin/vendor use the same browser cookie and cannot simultaneously retain separate identities in one browser profile.
- Existing address book is browser-local; order-derived profile is account-scoped but not editable as a separate address book.
- Lint script is not configured in the workspace packages. Local build reports sourcemap and large-chunk warnings.

- Vendor statement bucket roll-forward is based solely on stored ledger entries, not reconciled to GL, orders or bank/payment evidence. The existing payout-hold calculation may remain overstated after a zero-amount PAYOUT_DISBURSED entry; investigate and reconcile source records before relying on payout-hold totals. The statement does not present that derived hold as reconciled.

- Integration evidence, 2026-11-13: courier summary now reports not integrated even if credentials are present; the SMS OTP placeholder reports `dispatched: false`. Neither establishes a provider connection. The isolated Chromium fixture exercised vendor login, support creation and statement display at 375px and 1280px, not all portal screens, accessibility or live services. Provider-backed delivery, KYC storage, Postgres concurrency and adversarial RLS remain untested.
- Courier auto-sync is disabled both at its cron and legacy direct-function boundaries; the unverified generic HMAC webhook also fails closed even for valid signatures. No provider-specific webhook/polling contract has been verified; there is no automatic status update until a real integration and sandbox tests are completed (see `docs/runbooks/courier-tracking-status.md`).
