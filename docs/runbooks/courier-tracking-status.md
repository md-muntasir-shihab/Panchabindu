# Courier automatic status — current state

As of 2026-11-13, automatic courier tracking is **not integrated**. The cron endpoint returns `NOT_INTEGRATED` after authorization. The legacy internal sync function also fails closed without changing orders or ledger; it previously simulated progress without querying a courier. A generic HMAC webhook endpoint exists but its envelope is not verified as the provider's actual contract. Even a correctly signed request now returns `NOT_INTEGRATED` and does not mutate an order or financial record. The webhook processor remains legacy code, not a verified provider adapter. Manual order and reconciliation workflows are distinct and must be checked against actual courier records by operators.

Before enabling automatic status for Pathao or Steadfast: obtain current official merchant-specific documentation and a sandbox account through an authorized process; implement provider-specific authentication, endpoints and exact status mapping; securely map each event to its existing provider and consignment; handle duplicate, delayed and out-of-order events and terminal transitions; distinguish delivery from COD remittance and do not invent collected amounts or payout/escrow entries; add bounded requests, timeouts, idempotency, durable retry and audit. Bangladesh Post has no verified automatic interface in this implementation; keep it manual unless its official interface is verified. Test with sandbox provider fixtures and isolated Postgres concurrency/replay and cross-order cases. Production credentials, provider connection, webhook registration, scheduled jobs, production writes and deployment require explicit authorization. No provider was contacted and no real booking or status action was performed in this work.
